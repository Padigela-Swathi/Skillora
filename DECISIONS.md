# Decisions log

| ID | Decision | Rationale / alternatives |
|---|---|---|
| D-01 | Next.js App Router (16.x) + React 19 + strict TypeScript + Tailwind 4; `@supabase/ssr` for cookie sessions. | Mandated stack; Netlify supports Next 16 via its OpenNext adapter. |
| D-02 | Supabase is the sole backend (Postgres, Auth, RLS, Edge Functions). The handoff's "Cloudflare R2" is **not** used. | User mandate (Supabase only, no extra spend). Nothing in V1 uploads files, so no object store is needed. |
| D-03 | AI = NVIDIA API (`integrate.api.nvidia.com`, OpenAI-compatible) called **only from Supabase Edge Functions**; key lives in the secret `NVIDIA_API_KEY`. Default model `google/gemma-4-31b-it` (non-reasoning, returns clean JSON), fallback `google/gemma-3-12b-it`; both overridable via `NVIDIA_MODEL`/`NVIDIA_FALLBACK_MODEL`. | Probed live on 2026-11-20: `meta/llama-3.3-70b-instruct` is end-of-life (HTTP 410); the "reasoning" models (nemotron, mistral-large-4) spend the token budget on hidden reasoning and returned no `content`. The model catalogue churns, so the model is configuration, not code. Edge Function wall-clock (150 s) fits generation; Netlify functions (10–26 s) would not. |
| D-03b | Fallback chain re-verified 2026-11-20 (evening): `minimaxai/minimax-m3.1-flash` returned HTTP 529 (overloaded) repeatedly, and `stepfun-ai/step-5-preview` stalled for >2 min on a real prompt (slow hidden reasoning), so the default chain is `poolside/laguna-xs-2.1` → `nvidia/nemotron-3.5-bolt-e4b`. `chatJson` also has a 100 s total budget so no retry chain can exceed the Edge Function limit. Treat the chain as operational config (`NVIDIA_FALLBACK_MODEL`), re-check it before launch. | Free-tier models churn and overload; a wrong default must be fixable without a redeploy. |
| D-04 | Code execution = Edge Function `run-code` → **Judge0 CE public instance** (primary) with **Wandbox** (fallback), behind one `Runner` interface. `JUDGE0_URL` (+ optional `JUDGE0_AUTH_TOKEN`) can point to a self-hosted Judge0 (e.g. free Oracle/any VM) without code changes. | Probed live: public Piston is whitelist-only since 2026-02-15 (unusable); Judge0 CE, Wandbox, Godbolt all executed code free with no key. Supabase Edge Functions are Deno isolates and cannot spawn gcc/javac, so "running the compiler on Supabase" is not technically possible; the Edge Function acts as the secure, rate-limited, authenticated gateway instead. Risk: public instances have no SLA (documented in SECURITY/DEPLOYMENT). |
| D-05 | Coding questions are stdin→stdout programs. Expected outputs are **computed by executing an AI-written reference solution** in the sandbox, never trusted from the LLM. Tests with failing reference runs are dropped; if <3 verified tests remain the question degrades to a spoken "explain your approach" question. | LLM-generated expected outputs are frequently wrong; verifying by execution prevents unfair "failed" runs. |
| D-06 | No Storage buckets. | Camera is never recorded, audio is never kept (handoff §13), no uploads exist in V1. Not creating unused buckets = smaller attack surface. |
| D-07 | Coding mix: Coding round = ceil(2n/3) coding questions (never the first), Technical = 1 (n≤6) or 2 (n=9), HR/Managerial = 0. | Handoff says "coding mixed into rounds" without numbers; prototype shows Technical Q4/6 as coding. Recorded assumption, tunable in `config`. |
| D-08 | "Per day" = calendar day in `Asia/Kolkata`. Failed/abandoned interviews are not counted. | Target users are Indian students; avoids a UTC day boundary at 05:30 IST. |
| D-09 | Speech-to-text = browser Web Speech API (free); typed fallback where unavailable. Interviewer voice = `speechSynthesis`. | Zero cost, matches design copy ("Use Chrome for the best voice results"). Server STT would need paid/hosted models. |
| D-10 | All state transitions of an interview (create, answer, finish, evaluate) go through SECURITY DEFINER SQL functions or Edge Functions; clients have SELECT-only on interview tables. | Prevents tampering with scores, counts, limits or other users' rows even with a valid JWT. |
| D-11 | Terms version constant lives in code (`TERMS_VERSION`) and is mirrored in the Edge shared config; a unit test asserts both match. Acceptance is stored per user (`profiles.terms_version`). | Handoff: "Terms updates are made in code and require re-acceptance". |
| D-12 | Google sign-in only; the design's dashed "G" placeholder is replaced with the standard Google "G" mark. | Handoff §12. |
| D-13 | Legal placeholders `[DATE]`/`[CONTACT EMAIL]` → config values; legal copy flagged for human legal review. | Must not invent legal facts. |
| D-14 | A service-role key for a **different** Supabase project was present in the build environment; it was not used. All backend work was done through the connected Supabase MCP for project `kqqkowftmlysomzlzzta`. | Using credentials of an unrelated project would be unauthorised. |
| D-15 | Test accounts for authorisation/E2E tests are created in the Skillora dev project via SQL with `@skillora-test.invalid` emails and removed after the run. | Google OAuth cannot be automated; RLS must still be tested with real JWT roles. |
| D-16 | `chatJson` treats a model that does not answer within 35 s (or is overloaded twice) as unhealthy: it moves to the next model immediately and remembers the model as unhealthy for 5 minutes (module-level, shared by parallel calls in a warm Edge Function isolate). Evaluation uses a 55 s per-call timeout. Chain stays `gemma-4-31b-it` → `laguna-xs-2.1` → `nemotron-3.5-bolt-e4b`. | Found live on 2026-11-22: the primary stalled for 90 s+ while the fallbacks answered in ~1 s; waiting 80 s on a stalled model made interview start fail. If the primary stays slow, set the secret `NVIDIA_MODEL` to a fast model to skip the first 35 s entirely. |
